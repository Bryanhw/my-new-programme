## 3. 任务 V4-1：登录后交互 —— 统一「您已登录」3 秒倒计时

### 3.1 现状（第 51 轮基线）

- 登录成功：`auth.js` 提示「登录成功，正在进入广场…」，**500ms** 后 `location.href = feed.html`（表单始终还在原地，跳转靠定时器）。
- 注册成功：提示后 **800ms / 3000ms**（按密保是否存上）跳 `feed.html`。
- 匿名进入：提示后 **700ms** 跳 `feed.html`。
- 已登录用户再进登录页：`#already-in` 卡片原地出现（`tabs / 登录 / 注册` 三块被隐藏），**无限期停留**，需手动点「去我的」或「退出登录」。
- 页头反正已有 `#already-in` 卡片结构（R50 轮次），是改造的现成基座。

### 3.2 目标行为（站主已拍板：统一 3 秒）

| 入口 | 现状 | V4 目标 |
|---|---|---|
| 登录成功 | 提示 500ms 后跳 | 表单/登录界面立即消失，原地出现大号「✅ 您已登录」，停留 **3 秒**后自动跳 `feed.html` |
| 注册成功 | 提示 800/3000ms 后跳 | 同上，表单消失出现「✅ 您已登录」，3 秒后自动跳 `feed.html`（密保没存上的警示仍要显示，可并入同一张完成卡并适当延长的提示文案，逻辑不变） |
| 匿名进入 | 提示 700ms 后跳 | 同上，出现「✓ 已匿名进入」3 秒后自动跳 `feed.html`（文案保留匿名语义，不写成「您已登录」） |
| 已登录再进登录页 | `#already-in` 无限期停留 | 出现「您已登录」卡片，停留 **3 秒**后自动离开登录页（默认回 `index.html`；是否去「我的」可在实现时以一行常量决定） |

### 3.3 改动要点

1. **完成态卡片**取代提示条跳转：复用/扩展 `#already-in` 的卡片范式，做一个「已登录完成态」区块（对勾图标 + 大字 + 副文案 + 可选倒计时数字），表单、tabs、错误摘要一并隐藏；`auth.js` 里登录/注册/匿名成功分支统一走这同一份 UI。
2. **3 秒是时序不是动画**：不需要动效，`setTimeout` 3 秒后跳转即可；`prefers-reduced-motion` 与此无关（但倒计时数字的跳动若做成动画也一并尊重）。
3. **取消/防重入**：进入完成态后禁用再次提交入口；`setLoading` 已把提交按钮转圈，完成态直接替换容器，不再依赖按钮状态。
4. **看门狗保留**：`watch()` 15 秒无响应的超时提示链路不动，只在成功回调里改 UI。
5. 跳转目标保持现状（`feed.html`）；如需统一改为首页可在实现时确认，默认不扩大本次范围。

### 3.4 验收标准（站主自测，电脑端 + 手机端）

- [ ] 登录成功：表单消失，出现「您已登录」，约 3 秒后自动进入广场，期间按钮不可重复点击
- [ ] 注册成功：同上（密保未存上时，完成卡要如实提醒去「我的」补登记）
- [ ] 匿名进入：出现匿名完成态，3 秒后进入广场，文案不含「登录」误导
- [ ] 已登录用户再次打开登录页：出现「您已登录」卡片，3 秒后自动离开登录页
- [ ] 手机 390px 下完成态卡片不溢出、不横向滚动、可读
- [ ] 回归：`static_checks.py` / `run_tests.py` 不回归，版本串 `?v=` 刷新并逐字节发版

## 4. 任务 V4-2：手机端页头「先逛逛」不再被挤成三行

### 4.1 现状根因

- `login.html`（及同结构的认证页）页头是 `brand（nowrap） + 「先逛逛」link-plain + 汉堡菜单` 三件套。
- `.wrap` 为 `flex` + `space-between` + `gap:12px` + 固定 `height:64px`；`.brand` 有 `white-space:nowrap`，汉堡按钮固定宽，而 ``.link-plain`` 的「先逛逛」**没有 `nowrap` 也没有 `flex: 0 0 auto`**——窄屏（约 320–390px）时 `justify-content:space-between` 的伸缩盒一旦宽度不足，`link-plain` 作为可收缩项把「先逛逛」折成**三个字三行**（每个字一行）。这就是「挤成 3 行」的直接原因。

### 4.2 修改方案（默认）

1. 给认证页页头内的 ``.link-plain``（至少「先逛逛」链接）加 `white-space: nowrap; flex: 0 0 auto;`，杜绝折行。
2. 在 `@media (max-width: 520px)` 里为认证页页头做一组窄屏收边：`gap` 收小、`brand-mark` 字号随已有令牌即可，必要时「先逛逛」在极窄屏缩短为图标化只读入口（如并入汉堡菜单）——**默认不做这一步**，先验证纯 `nowrap` 是否已让三件套在 320px 下不折行、不横向滚动。
3. 检查**其余认证页**（`reset.html` 等）是否有同结构页头，一并修复，避免只修一页留一处。
4. 顺手复核首页/广场等六个页头（`.header-login` 已按 42px 图标处理过）在 390px 下不回归。

### 4.3 验收标准

- [ ] 手机 390px（及 320px）下「先逛逛」单行显示，不再是三行
- [ ] 页头三件套（品牌 / 先逛逛 / 汉堡）不交叠、不横向滚动
- [ ] 点击目标「先逛逛」热区 ≥38px，键盘可聚焦
- [ ] 所有同结构认证页（login / reset / 冒烟覆盖）一致修复
- [ ] 回归：静态检查 / 运行测试不回归；发版逐字节一致

## 5. 任务 V4-3：主页 hero —— 两扇打开窗外的动态操场与远山

### 5.1 现状（第 35–42 轮的「天空窗」）

- `.hero` 已是可视场景：渐变天空（`sky-high → mid → low → haze`）+ 两层动画云（`::before/::after` + `sky-drift-far/near`，`prefers-reduced-motion` 时静止）+ 中央校门图 `hero-gate`（`school-gate.png`，AI 生成抠底）。
- 已有约束：四边羽化 mask、圆角、`overflow:hidden`（云裁在窗里）、小屏羽化收到 40px、`hero-gate` 白晕贴纸化。

### 5.2 目标场景（站主描述）

> 两边两扇打开的窗户，对着操场；远处是干净的山和飘动的云。

即把 hero 从「单张校门图的天空窗」升级成一个**有纵深和动态的场景**：

- **左右两扇打开的窗**（近景，视觉取景框，从内向外看的姿态）；
- **中间望向操场**（中景：草地 / 跑道的透视地面，作为「对着操场」的落点）；
- **远处干净的山**（远景分层山影，青/雾蓝，干净不杂）；
- **飘动的云**（沿用现有云层平铺动画，可加一层更慢更淡的远雾）；
- **动态**体现在云的漂移与（可选的）窗的「打开」入场动画；
- 诉求内容（问候语 / 标题 / 副文案 / 匿名署名 pills / CTA 发布按钮 / 快捷键提示）保持在场景**之上**，对比度与可读性不因场景降级。

### 5.3 实现方案（默认：纯 CSS / SVG 分层场景，零新大图）

| 元素 | 拟实现 | 备注 |
|---|---|---|
| 操场地面 | SVG 或渐变绘制的透视椭圆 + 跑道环（含内沿），配色与既有 `--sky-*` / 金色令牌一致 | 低饱和，不抢文字；移动端可降清晰度 |
| 远山 | 2–3 层 SVG 山影（不同明度/雾感），最远层可挂极缓的水平视差漂移 | 干净：用青灰蓝阶梯调，不用照片 |
| 云 | 保留 `::before/::after` 两套平铺动画，可新增第三套更远更淡的缓动云层 | 动画全部保留在 `@media (prefers-reduced-motion: reduce)` 停止的既有框架内 |
| 左右窗 | 近景左右窗框（CSS 边框 + 玻璃折射高光；「打开」= 进入时一次 `transform: rotateY/scale` 的开窗入场动画，仅一次、尊重 reduced-motion） | 移动端收窄/弱化，避免挡标题 |
| 校门图 | **决策点**：保留作操场中央视觉锚点，或移除让场景更干净 | 方向确认时定，见 §5.5 |

### 5.4 动态与性能红线

- 动画只动 `transform` / `background-position-x` / `opacity`，不触发 layout；云漂移延续现有思路。
- `prefers-reduced-motion: reduce` 下所有动画（云 / 视差 / 开窗）静止，场景仍完整可读。
- 手机端（390px）：窗弱化为侧边装饰或隐藏、山与操场降低细节、hero 圆角与羽化沿用现有小屏规则；首屏高度不被撑爆（视觉参考现有 `min(34vh, 300px)` 的远景控制）。
- 不引入 JS 动画库、不加超大位图（避免破坏“零构建、低运维”基线）；若用插图素材则压缩并换 `WebP`/压缩 PNG，长度参考 ≤ 120KB/张）。

### 5.5 流程与决策点（沿用既有“先出方向再实现”的工作流）

1. 实现前先出一份**低保真方向稿 / 线稿**（纯文档或 `outputs/v4-hero-design.md`），站主确认场景构图（窗的开合角度、操场透视、远山层数、校门图去留、云量）后再落样式；
2. 若站主想要照片级质感而非 CSS/SVG 写实，备选为 **AI 生成主场景图 + CSS 云叠层**（沿用 `school-gate.png` 的抠底/白晕套路），走 `tools/make_icons.py` 类的脚本化素材流程；
3. 每个视觉参数（颜色走 `--sky-*` / `--ink-*` 令牌）受既有静态护栏约束（颜色只走令牌、对比度棘轮等），改动不得绕过护栏，需要在 `static_checks.py` 补相应新护栏。

### 5.6 验收标准

- [ ] 桌面 1440px：左右两扇打开的窗、中间操场、远处山与云，视觉干净、无锯齿、无横向滚动
- [ ] 云层持续漂移；`prefers-reduced-motion`（或系统“减弱动态效果”）下云、山、开窗动画全部停止且场景完整
- [ ] hero 内问候 / 标题 / pills / CTA 全部可读，对比度不被场景稀释（护栏守住）
- [ ] 手机 390px：场景不挤不溢、标题与按钮不被窗框遮挡、无横向滚动、首屏高度合理
- [ ] 性能：hero 无新增大图导致首屏变慢；LCP 不显著劣化（参考第 17 轮体检口径）
- [ ] 回归：静态检查 / 运行测试不回归；逐字节发版

## 6. 任务 V4-4：高校选择器 —— 全量 985 / 211 + 港五澳三 + 知名高校，拼音索引 + 搜索

### 6.1 名单口径（站主已确认）

- **985 工程：39 所**（含国防科技大学）；
- **211 工程：112 所**（= 39 所 985 + 73 所非 985）；其中中国矿业大学 / 中国地质大学 / 中国石油大学各有异地独立办学实体（北京 / 徐州 / 武汉 / 华东），选校时按**可识别的办学实体**列出校名（约 115 个可选实体），保证同学能准确选到自己的学校；
  - 列表建成后用一次性只读脚本与权威 985 / 211 名单**逐校比对差额并留痕**，防遗漏防错收；
- **港五澳三：香港大学、香港中文大学、香港科技大学、香港理工大学、香港城市大学 + 澳门大学、澳门科技大学、澳门城市大学**（澳三按站主确认；现有列表已含港五澳二，新增澳门城市大学即可）；
- **点名的知名高校：南方科技大学、深圳大学、中国科学院大学、深圳理工大学、香港中文大学（深圳）、西湖大学**（其中南科大、深大已在现有列表；国科大、深理工、港中深、西湖为新增；港中深需走既有 `DIFFERENT_CAMPUS` 护栏区分于「香港中文大学」——该护栏已有，直接纳入）。

### 6.2 决策点：只增不删（推荐）vs 严格裁剪

- **推荐：只增不删** —— 新列表 = 现有 129 校 ∪ {985/211 中缺失的} ∪ {澳三} ∪ {点名六所}。理由：现有近 200 所里的非 985/211（如广东工业大学、燕山大学、湘潭大学、东北财经大学、杭电设等）是**真实用户的学校**，删除会让他们的城市圈 / 同城归属消失，与项目“找不到就降级”的宽容哲学相悖；“知名度较高”本身就是模糊边界，只增不删最平滑。
- **备选：严格裁剪** —— 只保留 985 / 211 / 港五澳三 / 点名六所及少数公认知名度高的区域强校。列表更“权威”，但有删校风险。
- 该决策实现前由站主一句话确认；默认按推荐推进并把算法写成**差量脚本**（新增清单可审计）。

### 6.3 数据形态（`campuses.js` 升级，API 向后兼容）

- 每条校名需要**可排序的拼音键**：方案 A（默认）在数据里内置「首字母（A–Z）+ 全拼」，一次性离线按权威拼音校准，零运行时依赖、可被静态护栏校验；方案 B 运行时用 `Intl.Collator("zh-Hans-CN", { sensitivity: "base", numeric: true })` 排序 + 缩写表算首字母。推荐 A（干净、可测），B 作兜底。
- **对外 API 保持兼容**：`schoolOf / cityOf / provinceOf / schoolOptions / cityCount / size / MAX_LEN` 不得破坏 `app.js / auth.js / circles.js / hotwords.js` 的既有调用（任务 D2/B5 的归一化与分圈逻辑零改动）。

### 6.4 选校组件（站主已拍板：复用于组件）
