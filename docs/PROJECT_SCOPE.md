## 1. 这个项目是做什么的

「校园拾光」是一个面向大学生的**校园生活分享网站**：打开网页，写一句话（最多 1000 字）或配一张照片（≤5MB，上传前自动压缩），就能把今天的日常、心事、校园风景分享出来。每条内容可以选择**匿名**或**署名**；其他同学在「内容广场」浏览、点 🤍、评论和回复。

一句话版本：**给校园里一个没有压力的分享角落——想说什么就说，想匿名就匿名。**

它同时是一个「低运维 Web 应用」的实践：纯静态页面 + Supabase 云端后端 + GitHub Pages 托管，零服务器、零构建工具。

## 2. 谁会使用它

| 角色 | 是谁 | 怎么用 |
|---|---|---|
| 浏览者（未登录） | 任何打开链接的人 | 可浏览广场；要发布/评论时选择注册或「匿名进入」 |
| 学生用户（账号） | 用手机号注册的同学 | 发布（可署名或匿名）、评论回复、管理/删除自己的内容、设置昵称 |
| 匿名访客 | 不想注册的同学 | 一键「匿名进入」，可发布、可评论；署名「匿名同学」或不留名 |
| 站点所有者（管理员） | 项目作者本人 | 审核帖子与评论（通过/驳回）、处理举报；使用 Supabase 控制台 + 本地审核小工具 |

当前主要受众：开发者所在校园圈子的同学（小范围试用阶段）。

## 3. 它解决什么问题

1. **「想发又不敢发」**：校园话题常常敏感（吐槽、求助、心事），实名平台有社交压力 → 每条内容可选匿名，且匿名在接口层就不可追溯（作者 id 对前端不可读）。
2. **发布门槛高**：不需要排版作业级的内容 → 一句话/一张图，1 分钟内发布完；图片自动压缩，手机可直接上传。
3. **内容环境噪音**：泛社交平台信息流嘈杂 → 单一校园场景的小广场，只看同学们的内容。
4. **开放互动难治理**：评论容易失控 → 「先发后审 + 举报 + 审核队列 + 下架/恢复」的轻治理闭环，站主几分钟就能维持秩序。
5. **个人项目不想运维**：不买服务器、不维护后端 → 静态托管 + 免费层的数据库/存储/Auth，上线后几乎零维护成本。

## 4. 核心功能（截至 2026-09-29 已全部上线）

| 模块 | 内容 |
|---|---|
| 主页 | 按时段问候、校园照片、发布 CTA、广场入口、身份提示 |
| 发布 | 文字 1–1000 字 + 1 张图 ≤5MB（拖拽/点选），上传前自动压缩（>300KB 才压、最长边 1600px、JPEG q0.8）；每条可选匿名或署名 |
| 匿名访客 | 一键「匿名进入」；首次署名时弹小窗让你决定「署个名字」还是保持匿名 |
| 注册 / 登录 | 手机号 + 学校 + 密码注册（伪邮箱方案，不发真实短信）；登录；配置缺失时页面给出引导 |
| 内容广场 | 已通过审核的帖子列表、🤍 点赞、💬 评论区、一键刷新 |
| 评论与回复 | 两级结构（回复的回复自动锚回顶层）；先发后审；署名跟随昵称；可删除自己的评论（连同其回复）；评论 1–300 字 |
| 审核 | 新帖先进入「审核中」，站主通过后才对他人可见；作者自己始终能看到自己的待审内容 |
| 举报 | 帖子和评论都可举报（6 类原因）；一人对同一内容只能举报一次；举报人有三态回执（处理中 / 已处理 / 未违规） |
| 昵称与署名同步 | 随时改昵称（≤20 字），保存后会刷新历史发言的署名；匿名内容保持「匿名同学」不动 |
| 隐私边界 | 帖子/评论的作者 id 在接口层不可读（列级授权 + 数据库视图）；手机号仅本人可见（脱敏显示） |
| 站主工具 | 本地审核台 `tools/review-console/review_console.py`：帖子队列 + 评论队列（只列有未处理举报的评论）+ 反馈列表（**只读**，可标「已处理」），demo 模式可离线预览 |
| 意见反馈 | 页头菜单里的独立页：设备（电脑/平板/手机/其他，按 UA 预选可改）+ 想改的地方（1–500 字）+ 选填联系方式；**无需登录**即可提交；表上只有 `insert`、没有 `select` 策略（只有站主经 `service_role` 读得到），也不记录账号 / IP / UA |
| 合规 | 七页一致的页脚免责声明；FAQ 用大白话解释匿名、审核、图片、举报、反馈等 12 个问题 |

## 5. 明确不做哪些事

**产品边界（本产品不做，避免范围蔓延）：**

- 不做私信 / 群聊 / 聊天室
- 不做关注、粉丝、转发、好友体系
- 不做原生 App（只做响应式网页）
- 不做真实短信、实名认证、短信找回密码流程（账号是轻量的）
- 不做富文本 / Markdown 编辑器（纯文本 + 一张图）
- 不做多校区 / 多租户 / 社区分区（一个站点、一个广场）
- 不做广告、付费、会员体系
- 不做站内通知 / 邮件推送
- 不做评论区的逐条匿名（评论一律跟随账号/访客昵称署名）
- 不自建服务器、不自研后端（后端能力全部用 Supabase 组合）

**关于「匿名到什么程度」的边界（第 13 轮明确）：** 匿名帖的洞号**同一个人是同一个号**
（由数据库按作者账号 + 盐派生，见 `PLAN_phase2.md` D1）。这意味着读者能把同一个人的匿名内容串起来
——这是**刻意的取舍**（换来「认得出又是这位同学」的可读性，以及能指代「#×××××× 那条」），
不是多租户/分区，也不改变「一个站点、一个广场」的产品边界。盐只存在数据库里，不进仓库；
洞号**不参与任何过滤或排序**，也不含账号或手机号。给读者的说法必须同时讲清代价
（见 `faq.html` 与 README「关于匿名的边界」）；如果后续发现这在校内场景里惹麻烦，
退路是换盐（一批号全换）或退回每帖一个编号。

**当前阶段不做、后续可评估的（已在优化建议文档登记）：**

- 图片展示优化三件套：统一展示盒比例 + 看原图入口、竖图不裁人、`srcset` + `decoding="async"`
- 话题标签筛选、置顶、卡片「⋯」完整操作区、「抱抱」等轻反应
- 审核台打包成更傻瓜的形态（当前是本地 Python 小工具）

## 6. 时间、平台、技术上的限制

**时间**

- 个人业余项目，无硬性 deadline；节奏是「小步改动 → 测试 → 部署 → 线上验收」。
- Phase 1 自 2026-09-25 启动，主体功能已在 2026-09-28 前后完成（详见 PLAN_phase1.md）。

**平台**

- 目标：现代桌面与移动浏览器（Edge / Chrome / Safari 近年版本）；验收视口以桌面 1440px、手机 390px 为基准。
- 不覆盖：IE、老旧内核浏览器、原生 App、桌面客户端。
- 外部依赖：GitHub Pages（静态托管，有部署延迟与偶发抖动）、Supabase（免费层）。

**技术**

- 前端是纯静态：无 npm、无构建、无框架；原生 HTML/CSS/JS。
- 后端能力（数据库/Auth/存储）全部来自 Supabase 免费层：需留意存储配额与流量；图片因此限制 ≤5MB 且上传前压缩。
- 安全边界：`publishable key` 允许出现在前端；**`service_role` 密钥绝不出现在网页、仓库或聊天里**，管理动作只在本机受控环境执行。
- 治理方式：帖子上线需人工点「通过」（先审后显）；评论「先发后审」（被举报后下架）。
- 网络：站点托管在 GitHub Pages，部分地区访问速度受网络环境影响。

## 7. 大致用什么技术

| 层 | 选型 | 说明 |
|---|---|---|
| 前端 | HTML + CSS + 原生 JavaScript | IIFE 风格；共享模块 `window.Campus` + 每页一个页面脚本；无框架、无构建；`assets/vendor/supabase.js` 本地引入 |
| 数据 | Supabase · Postgres | 表 + 行级安全（RLS）+ 列级授权 + definer 视图（隐私边界）；触发器保证两级评论 |
| 认证 | Supabase Auth | 手机号包装成伪邮箱（`手机号@students.local`）注册/登录；匿名会话 |
| 存储 | Supabase Storage | `post-images` 桶：公开读、登录上传、文件所有者可删 |
| 托管 | GitHub Pages | `main` 分支直发；根目录 `.nojekyll` |
| 审核工具 | Python 标准库（本地运行） | 帖子/评论队列 + 只读反馈列表；真实模式用 service_role，仅本机；「已处理」标记只落本机 json，不回写数据库 |
| 质量工具 | Python + dukpy/esprima + Edge CDP | 静态检查与 DOM 桩运行测试（不引入 node 工具链）；无头浏览器线上验收 |

## 8. 怎样算成功

**Phase 1 的成功（进入下一阶段的硬标准，详见 PLAN_phase1.md 第 4 节）：**

1. 站主实测：电脑端 + 手机端都能正常走完整流程；
2. 其他同学实测：能以**匿名**和**账号**两种方式正常发表想法。

**项目级成功（持续观察）：**

- **能用**：新同学不需要教程，手机上 1 分钟内完成「打开 → 发布 → 看到自己的内容」。
- **可信**：匿名不泄露（接口层验证：作者 id 不可读）；举报有回执、有处理。
- **可运营**：站主日常仅需几分钟处理队列；不动代码即可运营。
- **成本**：全程运行在免费层内，无服务器运维。
- **可维护**：每次改动都有测试与线上验收记录（当前基线：静态检查 604 项、运行测试 567 项、线上端到端 29 项、审核台自检 67 项全部通过）。

**软指标（可选参考）**：上线后有一批真实同学使用——例如 ≥10 位同学发布过、累计 ≥50 条真实内容，且有人重复回来发布。
